# FantaStick 公式サイト

FantaStickの公式サイトのソースコードです。実行委員会の担当が変わっても、
下記の手順どおりに進めれば、プログラミングの知識がなくても更新できます。

## サイトの仕組み（先に知っておくこと）

- サイトの見た目・レイアウトは `index.html` が担当（**通常は触らなくてOK**）
- 毎年変わる情報（開催日・会場・料金・フォームURLなど）は `content.js` が担当
  → **通常の更新作業は `content.js` を編集するだけです**

---

## 毎年の更新手順（ブラウザだけで完結）

パソコンに何もインストールしなくても、GitHubのサイト上で直接編集できます。
ターミナルやgitコマンドは使いません。

### 手順1：GitHubにログインする
このリポジトリのアカウント情報は実行委員会内で引き継がれているはずです。
分からない場合は前任者、または実行委員会の代表に確認してください。

### 手順2：`content.js` を開く
リポジトリのファイル一覧から `content.js` をクリックします。

### 手順3：編集モードにする
画面右上の鉛筆アイコン（`✏️ Edit this file`）をクリックします。

### 手順4：決まった情報を書き込む

| 決まったこと | 書き換える場所 | 書き方の例 |
|---|---|---|
| 開催日 | `eventDate` | `"2027年2月21日（日）"` |
| 　〃　確定した | `eventDateConfirmed` | `false` → `true` |
| 会場名 | `venue.name` | `"かながわアートホール"` |
| 会場住所 | `venue.address` | `"〒240-0017　横浜市..."` |
| 会場アクセス | `venue.access` | `["相鉄線「星川駅」より徒歩20分"]` |
| 　〃　確定した | `venue.confirmed` | `false` → `true` |
| 観覧チケット申込フォーム | `ticketFormUrl` | `"https://forms.gle/xxxxx"` |
| SticKINGエントリーフォーム | `entryFormUrl` | `"https://forms.gle/xxxxx"` |
| 当日タイムテーブル | `programFlow` | `["開場", "開演", "..."]` |
| 　〃　確定した | `programConfirmed` | `false` → `true` |
| チケット・参加費（変更時のみ） | `tickets` の中の数字 | `1000` のように数字だけ |
| 前回大会のダイジェスト動画 | `lastYear.highlightVideoUrl` | `"https://www.youtube.com/embed/xxxx"` |

**注意点（ここを間違えるとサイトが正しく表示されません）**
- 文字列（言葉）は必ず半角の `"`（ダブルクォート）で囲む
- 各行の最後にある `,`（カンマ）は消さない
- 迷ったときは、書き換える前の元の形（クォートの位置・カンマの数）をそのまま真似する

### 手順5：保存する（コミットする）
ページ下部の「Commit changes...」を押します。
コメント欄に何をしたか一言書いておくと、後から見返しやすいです（例：「開催日を確定」）。
「Commit directly to the main branch」を選んで保存すればOKです。

### 手順6：数分待って確認する
1〜2分ほどで自動的にサイトに反映されます。公開URLを開いて表示を確認してください。

---

## うまく反映されない・エラーが出たとき

- 保存しようとしたときに赤い印やエラーメッセージが出たら、書き方
  （クォートやカンマ）が間違っている可能性が高いです。手順4の表を見直してください。
- 反映後にサイトが真っ白・崩れて見える場合も、同じ原因のことが多いです。
  「History」タブから直前の状態と見比べてください。
- 自分で直せないときは、無理に進めず、変更を一つ前の状態に戻して
  （Revertして）、分かるメンバーに相談してください。

---

## `content.js` の範囲を超える変更をしたいとき

デザインの変更、新しいセクションの追加、フォームの仕組みを変えたいなど、
`content.js` の書き換えだけでは対応できない変更は、Claude Codeなどの
開発ツールに依頼してください。その際は同梱の `FantaStick_HP_要件定義.md` を
渡すと、経緯を理解した状態で依頼できます。

## 公開の仕組み（参考）

このサイトは GitHub Pages（または Vercel）で公開されています。
`main` ブランチに変更が保存される（push / commitされる）と、自動的にサイトへ反映されます。
